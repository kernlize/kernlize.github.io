On this page

Alpha status ​

kernl is a first draft. This page says what runs, what is a contract without an implementation, and which upstream gaps are still to be filed. It is updated in the same pull request as the code it describes.

What works ​

AreaPackageState
Guard@kernl/guardThree profiles (createGuardConfig, applyNappletRules), envelope classification, ingress flood control with quarantine, visibility gate, focus-aware firewall over @kehto/firewall's evaluate(), the fixed zero-network CSP, a port of kehto's unreleased nested-frame lock (D-014), eleven mitigation descriptions for the UI. Pure, fully specified in packages/guard/features/.
Messaging@kernl/messagingMessagingProvider, MessagingBackend, MessagingRegistry with saved-preference restore, the composite backend with provider:innerId namespacing, describeProvider rows, a complete in-memory backend (createMemoryBackend) used by the preview and the tests, and three providers (private, legacy, ratchet) built with defineProvider from backends the shell injects.
Bridges@kernl/bridgesLocator parsing for the web schemes, magnet:, nzb:, slsk: and mailto:, the Bridge contract, the registry with its authorize hook and outcome events, a complete HTTP bridge with SSRF policy, the four backend-driven bridges up to their backend interface, createHandoffBackends, which serves all four by opening the locator in an app on the user's device, createBridgeResourceResolver for kehto's resource service, and describeBridge rows.
Composition@kernl/corecreateKernl over one applesauce EventStore, RelayPool and AccountManager, with kehto's real createShellBridge exercised end to end in kernl.feature: an applet is decoded, resolved, planned and mounted, binds its port through the guarded handleWindowMessage, completes shell.ready, is answered by the theme, identity and resource services, and is quarantined and revoked when it floods. Relay tiers, the applesauce adapters, the guard pipeline and runtime firewall rules, grants over bridge.runtime.aclState, consent summaries, the default registries and the layouts each have their own feature file.
Shell UIapps/webLanding site at / and the shell at /app/: sign-in (browser extension, remote signer, read-only, password-protected local account), open by address with the required and optional domains as choices, windows, a grants panel per window, a shell-wide guard panel with the event log, the provider picker, and the offline preview behind ?preview=1 (D-011), hosted at kernlize.github.io/app/?preview=1.

"Works" means the behaviour has a scenario in packages/*/features/, the scenario passes, and the page describing it exists. It does not mean the API is stable. Every package is 0.1.0; on 0.x a breaking change is a minor bump.

Messaging providers in the live shell ​

createDefaultMessaging registers all three providers, and each reports itself unavailable with a reason from MESSAGING_UNAVAILABLE_REASONS until the host passes a backend factory in KernlOptions.messagingBackends:

ProviderReasonWhat is missing
privateneeds-local-key-signerkehto's sealed-message adapter wants the owner's raw secret key, which kernl never holds outside an applesauce signer. A backend built from a signer the host controls makes it available.
legacynot-implementedNo backend exists for the original direct-message format.
ratchetno-runtimeA double-ratchet runtime has to be supplied.

apps/web supplies none of them, so the live shell's provider picker shows all three greyed with these reasons. The preview uses the in-memory backend.

What does not work yet ​

  • In-shell transfer backends. Downloads, sharing and mail work only by hand-off: createKernl passes host.openLink to createDefaultBridges, so the torrent, NZB, Soulseek and mail bridges open the locator's canonical address in an app on the user's device after the user confirms leaving kernl. kernl makes no connection for these; what the device app then does on its own network is outside kernl's view and control. No backend moves the data inside the shell, and there is no downloads view. A job result from a hand-off is an id, not a transfer kernl can track, and it is reported even when the user declines to leave. See Bridges.
  • Real messaging backends. The table above. See Messaging.
  • Web fetch from the browser shell, beyond the simple case. The HTTP bridge runs in the page, so it is subject to CORS, and an opaque redirect it cannot inspect is refused with denied:redirect-unverifiable. Web fetch works from the shell for https origins that permit cross-origin reads and answer without a redirect. Hostnames are checked as literals only; no resolver is wired. See Bridges.
  • Per-host bridge consent. createKernl builds the bridge registry with createDefaultBridges() and no authorize hook, so a resource request from a granted applet is checked by the HTTP bridge's SSRF policy and nothing else. A host that wants a prompt per host or scheme passes its own registry in KernlOptions.bridges.
  • Per-applet guard profiles. GuardFacade.setProfile rebuilds the pipeline for the whole shell and is not persisted. The per-applet, remembered override D-003 describes is not in this draft.
  • Mobile layouts beyond the basics. The layouts are desktop tilings over @kehto/wm (Layouts). At 720 px wide and below the shell switches to a compact layout: every window fills the desktop, and the bar keeps Open and moves the guard, messages, layout, minimised windows, settings and sign-out into a Menu sheet; panels open as full-width sheets. There are no gestures.
  • Multi-account switching. AccountManager holds several accounts and the sign-in panel lists them, but switching means signing out and in.
  • Grant persistence across devices. Grants, relay tiers and messaging preferences persist in the host's storage only. There is no sync. Every key is listed in Persistence.
  • Packages on npm. The @kernl/* packages are not published; they are used from a clone of the source repository, which is private during the alpha. See Packages.
  • Source links in the API reference. typedoc.json sets packageOptions.disableSources: true, so the generated reference has no "Defined in" source links. They would point at the source repository, which is private during the alpha.

The Roadmap orders this list.

Upstream gaps ​

kernl composes kehto rather than forking it (D-001). Four seams in kehto are narrower than kernl wants. All four are to be filed upstream against kehto/web, rather than patched locally; no upstream issue exists for them yet. Each has a kernl layer that shrinks when it lands (D-012):

  1. ShellAdapter does not forward getFocusContext, onFirewallEvent or firewallPersistence to the runtime. Without getFocusContext the runtime firewall treats every window as focused. kernl runs its focus-aware firewall in @kernl/guard, in front of the bridge for the window-level hello and as an observer of port traffic, using the pure evaluate() engine with visibility supplied by the host. Because that layer never supplies initElapsedMs, kehto's init-burst guard does not fire there, and the guard config's burstGuard is unused. The runtime does supply it, so the runtime's own startup burst guard (kehto's default, 20 operations in the first 3 s, block) refuses before dispatch. Without onFirewallEvent the runtime's refusals reach the applet as firewall: errors but not the host, so the guard panel shows kernl's own count of the same rates.
  2. createRuntime hardcodes the ACL default policy to 'permissive'. kernl produces its restrictive posture with KernlGrants.ensure, which writes an explicit grant or revoke for every capability of every applet it plans, plus capabilities.resolveEnvironment, which narrows the advertised domains to the baseline and the user's grants. The permissive default is never reached for an applet kernl runs.
  3. There is no hook that can hold or drop port traffic. kehto calls onNappletMessage synchronously before it dispatches each envelope, but ignores its answer, so kernl's ingress guard, visibility gate and focus firewall can count and report an envelope but not refuse or delay it on their own. They have two effects. One is quarantine: revoking the binding inside the hook stops the envelope that crossed the limit, because kehto then finds no session for the window. Refusals come from the runtime's own firewall, configured through applyRuntimeFirewallRules. The other is the size cap, refused through that firewall: the runtime sizes only an envelope's event, so its matchers never see a download or a query, and kernl, which does measure them, sets the applet's runtime policy to deny for that one synchronous dispatch (refuseCurrentDispatch). Deferral while hidden is advisory for port traffic. See Guard.
  4. The runtime firewall never applies an unfocused multiplier. Because of gap 1 the runtime sees every window as focused, so its multiplier, whatever the value, never applies; and FirewallStateContainer has no setter for unfocusedMultiplier, so kernl could not install the profile's value even if focus were forwarded. The profile's value is applied only by kernl's focus firewall, which reports overruns rather than refusing them.

A fifth observation, not a gap kernl needs closed: the transport internals createNip5dTransport and createShellReadyState are not exported, so kernl uses createShellBridge unchanged.

One mitigation is carried locally rather than waiting upstream: @kehto/shell 0.29.0 leaves an applet free to create a child frame whose fresh realm still has WebRTC, and the lock that closes this exists only on kehto main behind experimental.nestedContextLock. @kernl/guard ports it and planMount always applies it, until a kehto release ships the flag (D-014).

Corrections ​

  • Rate enforcement (corrected 2026-11-03). Earlier drafts of these docs, the README and D-012 said kehto's runtime firewall refused envelopes over the profile's rates. It did not: applyRuntimeFirewallRules also set each applet's runtime policy to allow, and kehto's evaluate() returns pass for an allow policy before it looks at any rate, matcher or burst. No rate was refused before dispatch; only kernl's reports and quarantine applied. The policy call is removed, the rates and kehto's startup burst guard now refuse before dispatch, and D-012 is rewritten to match.
  • Size caps (corrected 2026-11-03). The guard's size matchers were described as able to report matcher:size:<class> in the shell. They cannot fire there: the ingress guard rejects the same envelopes first. Oversized downloads and queries were reported but still handled; they are now refused before dispatch.
