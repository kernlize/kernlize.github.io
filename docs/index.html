kernl ​

kernl is an opinionated shell for sandboxed web applets. It is built on kehto, the unopinionated NIP-5D toolkit, and it treats the person at the keyboard as the only principal who matters.

A shell has two jobs. It gives the user a place where their identity, relays, contacts, media and messages are theirs and portable. And it gives an untrusted program a place to run where the worst it can do is bounded. kernl does both, and when kehto offers a way to bound an applet further, kernl turns it on by default.

Alpha

kernl is a first draft. The four packages build, the contracts are stable enough to document, and the shell runs. Several backends are contracts without implementations. Read Alpha status before depending on anything here.

What kernl decides that kehto leaves open ​

kehto ships @kehto/{acl,firewall,runtime,shell,services,nip,wm} and deliberately does not pick a relay library, a signer, a consent model, a layout engine or a deployment story. kernl picks all of them:

Opinionkernl's choice
Event layerapplesauce v7 only. One EventStore, one RelayPool, one AccountManager per shell. nostr-tools is never imported by kernl source.
ContainmentOpaque-origin srcdoc iframe, sandbox="allow-scripts", zero-network CSP, every network path through a shell service the user can see, rate-limit and revoke.
MitigationsEvery kehto mitigation ships on, in the strict guard profile. The user loosens per applet; a developer never loosens globally.
ProtocolsOne identity layer, many bridges named by what they do for the user, never by the wire format.
MessagingAny reasonable private-messaging protocol, exposed through one contract. Providers describe their security properties truthfully and the shell does not rank them.

kernl does not fork kehto. When kehto lacks a hook kernl needs, kernl composes around it and files the gap upstream. The four gaps filed so far are recorded in D-001.

Three doors ​

Use the shell. Run kernl locally, sign in with a browser extension or a remote signer, and open an applet by its address. Start with Run the shell, then read Grant and revoke to understand what the shell asks you and why.

Build an applet for it. Applets are ordinary NIP-5D napplets; kernl adds nothing to the wire format. What kernl changes is the posture: fewer domains advertised until granted, deferral while hidden, and rate limits that tighten when you lose focus. Build an applet for kernl tells you what to expect and how to test against it.

Extend the shell. Add a messaging provider, a bridge backend, or change how the guard is composed. Start with Architecture and the package pages.
