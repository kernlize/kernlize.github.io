@kernl/bridges ​

Locator parsing, the bridge contract, the registry that routes and authorises, an HTTP bridge with an SSRF policy, four backend-driven bridges for downloads, sharing and mail, hand-off backends that open an app on the user's device, the adapter that feeds a resource service, and user-facing descriptions. Zero dependencies.

Peer dependenciesnone

Install ​

@kernl/bridges is not yet published to npm, so pnpm add @kernl/bridges fails. During the alpha it is built from the kernl source repository, which is private, and consumed as a workspace dependency. The package index has the steps.

json
{ "dependencies": { "@kernl/bridges": "workspace:^" } }

Purpose ​

A bridge resolves a protocol-specific locator to bytes, a job or a conversation on the user's behalf, behind the same grant and quota as everything else (the composed shell wires no per-request consent), and is named by what it does rather than by its protocol. The HTTP bridge is complete. The torrent, NZB, Soulseek and mail bridges are complete up to the backend interface they call; createHandoffBackends supplies all four by handing the locator to an app on the user's device, createWebTorrentBackend downloads magnet links inside the page instead (D-017), and without any backend they report unavailable. The concepts are in Bridges; the opinion is D-010.

Locators ​

HTTP bridge ​

ExportSignatureDescription
createHttpBridge(options?: HttpBridgeOptions) => BridgeId http, label downloads. Allowed schemes only, no private or local destinations (re-checked on every redirect hop and, with resolveHost, after name resolution; without it hostnames are judged as literals), a redirect cap, a time limit and a byte limit enforced on the streamed body. In a browser an opaque redirect is refused with denied:redirect-unverifiable, and CORS applies.
HttpBridgeOptionsinterface{ policy?: Partial<HttpPolicy>; fetch?: typeof fetch; resolveHost?: (host: string) => Promise<readonly string[]> }.
DEFAULT_HTTP_POLICYHttpPolicy{ allowedSchemes: ['https:'], maxRedirects: 3, maxBytes: 10485760, timeoutMs: 20000, allowPrivateHosts: [] }. Scheme entries carry the colon, as URL.protocol does.
HttpPolicyinterfaceallowedSchemes, maxRedirects, maxBytes, timeoutMs, allowPrivateHosts.
isPrivateAddress(ip: string) => booleanTrue for literal IPv4 or IPv6 addresses in the unspecified, loopback, private, shared, link-local, IETF protocol assignment, benchmarking, multicast or reserved IPv4 ranges, and the link-local, site-local, unique-local, multicast, discard, local NAT64, 6to4 or Teredo IPv6 ranges. IPv6 is parsed to its full 128 bits (brackets and zone suffix stripped); an address that embeds an IPv4 destination (mapped, compatible, translated, NAT64 64:ff9b::/96) is judged by that destination. False for public addresses and for strings that are not an IP. Ranges are listed in Bridges.
isBlockedHostname(host: string) => booleanTrue for localhost and names under .localhost, .local or .internal, in any case, with or without a trailing dot.

Backend-driven bridges ​

ExportSignatureDescription
createTorrentBridge(backend?: TorrentBackend) => BridgeId torrent, label downloads, scheme magnet. Exposure: reveals address, not encrypted, public activity.
createNzbBridge(backend?: NzbBackend) => BridgeId nzb, label downloads, scheme nzb. Exposure: reveals address, encrypted, not public.
createSoulseekBridge(backend?: SoulseekBackend) => BridgeId soulseek, label sharing, scheme slsk. Exposure: reveals address, not encrypted, public activity.
createMailBridge(backend?: MailBackend) => BridgeId mail, label mail, scheme mailto. Exposure: does not reveal address, encrypted, not public.
BackendTraitsinterface{ handoff?: true | undefined }. Every backend interface extends it; a hand-off backend sets it, and its bridge then reports { available: true, handoff: true }. The bridge reads it on every availability check, so a backend may switch it, as the shell's does when the user changes where downloads go.
TorrentBackendinterfaceadd(infoHash: string, trackers: readonly string[], context: BridgeContext, name?: string): Promise<{ id: string; name: string }>. name is the magnet's display name when it has one.
NzbBackendinterfaceadd(url: string, context: BridgeContext): Promise<{ id: string; name: string }>.
SoulseekBackendinterfacedownload(user: string, path: string, context: BridgeContext): Promise<{ id: string; name: string }>.
MailBackendinterfaceopen(address: string, subject: string | undefined, context: BridgeContext, body?: string): Promise<{ id: string }>.

Without a backend each of the four reports { available: false, reason: 'no-backend' } and resolve() rejects with unavailable:no-backend. A locator missing a field the backend needs rejects with invalid:locator-missing-<field> before the backend is called.

Hand-off backends ​

ExportSignatureDescription
createHandoffBackends(open: HandoffOpener) => HandoffBackendsOne backend per bridge, each with handoff: true. Each rebuilds the canonical address from the parsed fields (a magnet: link with hash, name and trackers; an slsk:// address; a mailto: address with subject and body; the NZB document's https URL) and passes it to open once. Ids come from one shared counter, handoff:1, handoff:2, and so on. The NZB backend throws invalid:nzb-not-https for a document not served over https.
HandoffOpenertype(uri: string) => void | Promise<void>. The shell passes host.openLink, which asks the user before leaving kernl.
HandoffBackendsinterface{ torrent: TorrentBackend; soulseek: SoulseekBackend; mail: MailBackend; nzb: NzbBackend }.

A hand-off makes no connection from kernl; the app on the device does the transfer with its own network, which kernl cannot see or limit. See Bridges.

Downloads inside kernl ​

NZB, Soulseek and mail have no in-page backend: their protocols need raw TCP sockets, which a browser page cannot open. See Bridges.

Example ​

ts
import { createBridgeRegistry, createBridgeResourceResolver, createHandoffBackends, createHttpBridge, createTorrentBridge, formatLocator, type ResourceResolveInit } from '@kernl/bridges';

declare const lookupAddresses: (host: string) => Promise<string[]>; // the shell's DNS lookup
declare const identityFor: (init: ResourceResolveInit) => { dTag: string; hash: string } | 'shell'; // the shell's window-to-identity map

const registry = createBridgeRegistry({
  authorize: (locator, bridge) => confirm(`Open ${formatLocator(locator)} with ${bridge.label}?`),
  onResolve: (event) => console.log(event),
});
registry.register(createHttpBridge({ resolveHost: lookupAddresses }));
const handoff = createHandoffBackends((uri) => {
  if (confirm(`Leave and open ${uri}?`)) window.open(uri, '_blank', 'noopener,noreferrer');
});
registry.register(createTorrentBridge(handoff.torrent)); // { available: true, handoff: true }

const result = await registry.resolve('https://example.com/file.bin', { requester: 'shell' });
if (result.kind === 'bytes') result.response.status;

// what @kernl/core hands to kehto's resource service
const fetchLike = createBridgeResourceResolver(registry, { requesterFor: (init) => identityFor(init) });

Scope ​

  • Does not implement any transfer protocol. The hand-off backends only build an address and open it; backends that move data live in the shell app or in packages of their own.
  • Does not prompt. Consent is a BridgeAuthorizer the host can supply to the registry; createKernl's default registry has none.
  • Does not apply the guard. Rate limits and the hidden-window allowance run in @kernl/guard before a request reaches the registry.
  • Does not know about NAP envelopes. @kernl/core maps resource.* requests onto createBridgeResourceResolver(registry).
