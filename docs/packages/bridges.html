@kernl/bridges ​

Locator parsing, the bridge contract, the registry that routes and authorises, an HTTP bridge with an SSRF policy, four backend-driven bridges for downloads, sharing and mail, the adapter that feeds a resource service, and user-facing descriptions. Zero dependencies.

Version0.1.0
Entry./dist/index.js, types ./dist/index.d.ts
Dependenciesnone
Peer dependenciesnone
Side effectsnone

Install ​

@kernl/bridges is not yet published to npm, so pnpm add @kernl/bridges fails. During the alpha it is built from the kernl source repository, which is private, and consumed as a workspace dependency. The package index has the steps.

json
{ "dependencies": { "@kernl/bridges": "workspace:^" } }

Purpose ​

A bridge resolves a protocol-specific locator to bytes, a job or a conversation on the user's behalf, behind the same consent and quota as everything else, and is named by what it does rather than by its protocol. The HTTP bridge is complete; the torrent, NZB, Soulseek and mail bridges are complete up to the backend interface they call and report unavailable until one is supplied. The concepts are in Bridges; the opinion is D-010.

Backend-driven bridges ​

ExportSignatureDescription
createTorrentBridge(backend?: TorrentBackend) => BridgeId torrent, label downloads, scheme magnet. Exposure: reveals address, not encrypted, public activity.
createNzbBridge(backend?: NzbBackend) => BridgeId nzb, label downloads, scheme nzb. Exposure: reveals address, encrypted, not public.
createSoulseekBridge(backend?: SoulseekBackend) => BridgeId soulseek, label sharing, scheme slsk. Exposure: reveals address, not encrypted, public activity.
createMailBridge(backend?: MailBackend) => BridgeId mail, label mail, scheme mailto. Exposure: does not reveal address, encrypted, not public.
TorrentBackendinterfaceadd(infoHash: string, trackers: readonly string[], context: BridgeContext): Promise<{ id: string; name: string }>.
NzbBackendinterfaceadd(url: string, context: BridgeContext): Promise<{ id: string; name: string }>.
SoulseekBackendinterfacedownload(user: string, path: string, context: BridgeContext): Promise<{ id: string; name: string }>.
MailBackendinterfaceopen(address: string, subject: string | undefined, context: BridgeContext): Promise<{ id: string }>.

Without a backend each of the four reports { available: false, reason: 'no-backend' } and resolve() rejects with unavailable:no-backend. A locator missing a field the backend needs rejects with invalid:locator-missing-<field> before the backend is called.

Resource resolver ​

ExportSignatureDescription
createBridgeResourceResolver(registry: BridgeRegistry, options?: BridgeResourceResolverOptions) => BridgeResourceResolverAdapts a registry to the fetch(url, init) seam of a resource service. bytes results return their Response; job and conversation results become a 202 Accepted JSON body. Failures reject with the registry's reasons.
BridgeResourceResolvertype(url: string, init: ResourceResolveInit) => Promise<Response>.

BridgeResourceResolverOptionsinterface{ requesterFor?: (init: ResourceResolveInit) => BridgeContext['requester'] }. Used when the init names no requester; the fallback is 'shell'.

Example ​

ts
import { createBridgeRegistry, createBridgeResourceResolver, createHttpBridge, createTorrentBridge, formatLocator } from '@kernl/bridges';

const registry = createBridgeRegistry({
  authorize: (locator, bridge) => confirm(`Open ${formatLocator(locator)} with ${bridge.label}?`),
  onResolve: (event) => console.log(event),
});
registry.register(createHttpBridge({ resolveHost: lookupAddresses })); // the shell's DNS lookup, (host) => Promise<string[]>
registry.register(createTorrentBridge()); // unavailable until a TorrentBackend is supplied

const result = await registry.resolve('https://example.com/file.bin', { requester: 'shell' });
if (result.kind === 'bytes') result.response.status;

// what @kernl/core hands to kehto's resource service
const fetchLike = createBridgeResourceResolver(registry, { requesterFor: (init) => identityFor(init) }); // identityFor: the shell's window-to-identity map

Scope ​

  • Does not implement any transfer protocol. Backends live in the shell app or in packages of their own.
  • Does not prompt. Consent is a BridgeAuthorizer the host can supply to the registry; createKernl's default registry has none.
  • Does not apply the guard. Rate limits and the hidden-window allowance run in @kernl/guard before a request reaches the registry.
  • Does not know about NAP envelopes. @kernl/core maps resource.* requests onto createBridgeResourceResolver(registry).
