@kernl/guard ​

Ingress flood control, visibility gating, focus-aware firewall, CSP profile and nested-frame lock for the kernl shell. Pure: no DOM, no timers. Every factory takes an optional now clock and defaults to Date.now.

Dependencies@kehto/firewall ^0.6.3

Side effectsnone

Install ​

@kernl/guard is not yet published to npm, so pnpm add @kernl/guard fails. During the alpha it is built from the kernl source repository, which is private, and consumed as a workspace dependency. The package index has the steps.

json
{ "dependencies": { "@kernl/guard": "workspace:^" } }

Purpose ​

The guard is the set of protections between an applet and the user. kehto's @kehto/firewall supplies a pure evaluate() engine; this package gives its opaque operation classes meaning, adds the layers kehto's ShellAdapter cannot yet host (ingress flood control, the visibility gate, focus supplied by the shell's window manager), fixes the CSP, carries a port of kehto's unreleased nested-context lock (D-014), and describes every mitigation for the UI. The concepts and the numbers are in Guard.

Frame lock ​

A temporary, attributed port of kehto's experimental.nestedContextLock (kehto 4d8a5693), which no @kehto/shell release carries yet. Removed when one does (D-014).

ExportSignatureDescription
appletMarkupHasFrame(html: string) => booleanTrue when the markup contains an iframe, frame, frameset, object, embed, portal or fencedframe element. Parses with the host's DOMParser when there is one, including inside <template> content; otherwise, or if parsing throws, a lexical match that may over-reject.
assertAppletHasNoFrame(html: string) => voidThrows Error('denied:nested-frame') when appletMarkupHasFrame is true. Call it on the verified bytes before they become a srcdoc; planMount does. The only export of this package that throws.
renderFrameLockScript() => stringAn inline <script data-kernl-frame-lock> that, run in the applet realm, installs a Trusted Types default policy refusing frame markup at every HTML string sink and pins Document.prototype.createElement, createElementNS and DOMImplementation.prototype.createDocument non-configurable to throw TypeError('denied:nested-frame') for frame tag names. Insert it immediately after kehto's namespace prelude, in a document whose CSP carries TRUSTED_TYPES_DIRECTIVES. A policy-name collision or a pre-frozen prototype is skipped rather than blocking the load.
TRUSTED_TYPES_DIRECTIVESstring"require-trusted-types-for 'script'; trusted-types default": routes every DOM string sink through the default policy and admits no other policy name.

Example ​

ts
import { applyNappletRules, createGuardConfig, createIngressGuard, describeMitigations } from '@kernl/guard';

const config = createGuardConfig('strict');
config.limits.ingressBurst; // 8
config.firewall.unfocusedMultiplier; // 0.25

const bound = applyNappletRules(config, 'chat');
bound.firewall.napplets['chat']?.rateLimits['relay:publish']?.capacity; // 20

const guard = createIngressGuard({ config, onEvent: (event) => console.log(event.reason) });
guard.admit('w1', 'chat', { type: 'relay.subscribe' }, { visible: true, focused: true }); // 'pass'

describeMitigations(config).find((m) => m.id === 'ingress-flood')?.limit; // '8 messages per second, 300 per 10s'

Scope ​

  • Pure functions and small stateful objects keyed by windowId. Call forget(windowId) on every revocation.
  • Does not parse NAP envelopes beyond type, kind and size; the shell passes those fields and may use estimateEnvelopeSize for the third.
  • Does not decide grants. Whether a domain is allowed is @kehto/acl's question, surfaced through @kernl/core.
  • Does not touch the shell's DOM or the iframe. The shell applies createAppletCsp(profile) through kehto's prepareNappletSrcdoc, and planMount in @kernl/core splices in the frame lock; the lock's script runs only inside the applet realm.
  • Does not supply initElapsedMs to kehto, so GuardConfig.firewall.burstGuard never fires inside this package. The startup burst that does fire is kehto's runtime firewall's own, at kehto's default of 20 operations in the first 3 s (Guard).
